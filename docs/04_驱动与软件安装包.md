# 04 — Win11 驱动与软件安装包（可直接执行）

> 本目录中的安装包全部来自**你自己的素材文件**，没有改动原文件夹。
> 目标是在 Windows 10/11 x64 上，用最短路径恢复 NJB3 的驱动与传输能力。

---

## 1. 本次实际制作了什么

| 产物 | 路径 | 说明 |
|---|---|---|
| USB 驱动包 | `drivers/creative_pde_usb/`（29 个文件） | `ctpdusb.inf` + x64 `ctpdusbx.sys` + x86 `ctpdusb.sys` + 2 个 `.cat` + WMDM/COM 用户态组件 |
| 1394 设备端驱动包 | `drivers/creative_pde_1394/`（28 个文件） | `ctpd1394.inf` + x64 `ctpdfwx.sys` + x86 `ctpd1394.sys` + 2 个 `.cat` + 同样的用户态组件 |
| 驱动安装器 | `scripts/install_win11_driver.ps1` | 管理员权限校验 → 复制到稳定路径 → 校验 `.cat` 签名 → HVCI 检查 → `pnputil` 注册 → COM 注册 → 绑定指引 |
| 1394 主机卡配置器 | `scripts/install_1394_host.ps1` | 检测 VIA/TI 火线卡 → 报告硬件 ID 覆盖状态 → 触发系统自带驱动重绑 → 安装 Creative 1394 设备端驱动 |
| CMS5 安装辅助 | `scripts/install_cms5.ps1` | 校验安装器、复制到无中文路径、静默参数安装（默认演练，需 `-Execute` 才真跑） |
| 体检脚本 | `scripts/verify_install.ps1` | 只读汇总：系统/HVCI/驱动库/1394 卡/NJB3 设备/CMS5/Python |
| 一键菜单 | `scripts/njb3_setup.cmd` | 上面所有脚本的中文菜单入口（**GBK + CRLF 编码**，适配中文 cmd） |
| 提权辅助 | `scripts/run_admin.ps1` | 菜单里统一走它弹 UAC，避免在 `.cmd` 里写复杂的嵌套引号 |

**没有"重新编译驱动"**：Creative 驱动是 WHQL 签名的二进制，无源码、无 WDK 工程，重写既无必要也不可能。
本次做的是把**已经可用的签名驱动**做成 Win11 上能正确安装的自包含包。这是互操作性修复的正确层级。

## 2. 关键证据（为什么这样装）

### 2.1 签名：签名在 `.cat`，不在 `.sys`

实测（`Get-AuthenticodeSignature`，本机 Win10 22H2，对原始素材）：

| 文件 | 状态 | 签名者 |
|---|---|---|
| `ctpdusb.sys` | Valid | Microsoft Windows Hardware Compatibility Publisher |
| `ctpdusbx.sys` | Valid | 同上 |
| `ctpdusb.cat` | Valid | 同上 |
| `ctpd1394.cat` | Valid | 同上 |
| `ctpdfwx.cat` | Valid | 同上 |
| `ctpdusbx.cat` | Valid | 同上 |
| `ctpd1394.sys` / `ctpdfwx.sys` | NotSigned | **正常**——老式 WDM 驱动靠 `.cat` 目录签名，不是嵌入签名 |

证书本身的有效期是 2005-08 至 2006-08（很老），但 Windows 当前仍将这些目录签名验证为 **Valid**，
所以**通常不需要**禁用驱动签名强制或进入测试模式。若你的机器策略更严格，按脚本输出的提示临时处理即可。

### 2.2 架构与硬件 ID

- x64 机器加载 `ctpdusbx.sys`（PE machine `0x8664`）/ `ctpdfwx.sys`。
- x86 机器加载 `ctpdusb.sys` / `ctpd1394.sys`（PE machine `0x014C`）。
- `ctpdusb.inf` 中 NJB3 的硬件 ID 是 `USB\VID_041e&PID_4101`，字符串 "NOMAD Jukebox 3"。
- `ctpd1394.inf` 中 NJB3 的硬件 ID 是 `1394\CREATIVE_TECHNOLOGY_LTD.&NOMAD_JUKEBOX_3`。
- 两个 INF 都注册 WMDM 服务提供者 CLSID `{DF878EB3-5A77-405C-BF36-FAF4916BD25C}`，
  这就是 CMS5 能识别机器的原因。

### 2.3 为什么原安装器在 Win7+ 失败

原始 `Creative_USB_x86_x64.rar` 里的 `CtDrvIns.exe` / `CtDrvIns64.exe` 是 2006 年的安装前端，
在 Vista 之后的 UAC/驱动库模型下解压与注册经常不完整。绕过它、直接用 `pnputil` + 设备管理器
从磁盘安装，是社区在 Win10 LTSC / Win11 上验证过的路径。

## 3. 安装步骤（推荐顺序）

### 步骤 A：装驱动

管理员 PowerShell：

```powershell
cd G:\Drivers\jukebox3_win11\scripts
.\install_win11_driver.ps1 -Mode Both
```

脚本会询问/提示的最后一步是在设备管理器中把 INF 绑定到设备（它无法替你点图形界面）：

- **USB**：设备管理器 → 未知 USB 设备 → 更新驱动 → 从磁盘安装 →
  `C:\Program Files\NJB3-Win11\creative_pde_usb\ctpdusb.inf` → 选 "NOMAD Jukebox 3"
- **1394**：先跑 `install_1394_host.ps1`，然后火线设备 → 从磁盘安装 →
  `C:\Program Files\NJB3-Win11\creative_pde_1394\ctpd1394.inf` → 选 "NOMAD Jukebox 3 1394"

装完用 `.\verify_install.ps1` 确认驱动库里出现 `ctpdusbx` / `ctpdfwx`。

### 步骤 B：装软件

```powershell
.\install_cms5.ps1                       # 演练，看命令
.\install_cms5.ps1 -Execute              # 静默真装（管理员）
.\install_cms5.ps1 -Execute -Interactive # 交互真装：弹检测窗时可插入设备点"重试"
```

> **重要：安装顺序的前提是先让设备被系统识别。** 这两个 EXE 是 InstallShield
> "Web Installer"，启动时会运行 Creative 产品检测（`CTDetctu.exe`）。如果系统里
> 没有识别到 Creative 设备（NJB3 = USB `VID_041e&PID_4101`），就会弹出
> **"安装程序在您的系统中检测不到支持的产品"** 并终止——这与脚本参数无关。
> 正确顺序：**插入 NJB3 → 设备管理器手动装好 `ctpdusb.inf` 驱动、确认设备出现 → 再装 CMS5**。
> 脚本已内置设备预检：未检测到设备且未加 `-Force` 时会直接中止并给出上述提示。

若静默安装失败，手动依次安装（顺序不能反）：

1. `CMS5_PCAPP_LB_5_10_38.exe`（主程序）
2. `CMS5_NJB2_PCAPP_LB_5_00_22.exe`（NJB2/NJB3 插件）

手动装若弹"检测不到支持的产品"：保持弹窗不关，**现在把 NJB3 插上**，点"重试"，
让检测器扫到设备即可继续。旧安装器在 Win11 上若提示解压失败，用 7-Zip 把 EXE
解包后运行其中的 `setup.exe`（交付目录 `tools/7za.exe` 可直接用：`7za x 安装包.exe`）。
注：`Data1.cab` 是 InstallShield 专有 `ISc(` 格式，通用解包器打不开，需装引擎本身。

### 步骤 C：传歌

- 图形界面：CMS5 → 从设备管理器导入曲目 → 同步。
- 命令行/批量：`python njb3_transfer.py --help`（自动读 ID3 写设备元数据、m3u 导入、文件夹建播放列表、设备设置）。

> **互斥提醒**：上面的原厂驱动路径与 libusb/Zadig + libnjb 路径**互斥**。
> 一旦用 Zadig 把设备换成 WinUSB，CMS5 就找不到机器了；反过来也一样。不要混用。

## 4. 回滚与排错

| 现象 | 处理 |
|---|---|
| 驱动装了但设备仍黄色感叹号 | 设备管理器 → 卸载设备（勾选删除驱动）→ 重插 → 重跑 `install_win11_driver.ps1` |
| 提示"数字签名有问题" | 检查 `.cat` 是否齐全；临时：重启 → 高级启动 → 启动设置 → 按 7（仅本次）；装完重启自动恢复 |
| HVCI 导致驱动加载失败 | Windows 安全中心 → 设备安全性 → 核心隔离 → 关闭内存完整性 → 重启（装完可再开） |
| CMS5 看不到设备 | 先跑 `verify_install.ps1` 确认驱动已绑定；重启后再插拔；确认没用 Zadig 换过驱动 |
| 想换回 libnjb 路线 | 卸载 Creative 驱动，Zadig 选 WinUSB/libusb-win32，然后用 `njb3_transfer.py` |
| 双击 `.cmd` 报 `'onPolicy' 不是内部或外部命令`、中文乱码 | 旧版菜单文件是 UTF‑8+LF，被中文 cmd 按 GBK 解析且换行不识别。**已修复为 GBK+CRLF**；若你自行编辑过，请用记事本另存为 `ANSI` 并确保 Windows 换行（CRLF），不要用 UTF‑8 保存 |
| 真装时报 `找不到：-Execute\CMS5_PCAPP_LB_5_10_38.exe` | 旧版提权脚本用数组展开传参，`-Execute` 被当成第一个位置参数塞进 `$SourceDir`。**已修复**：`run_admin.ps1` 把开关作为显式命名参数传递；`install_cms5.ps1` 也加了防御性恢复 |
| 弹窗"安装程序在您的系统中检测不到支持的产品"（重试/取消）| **不是脚本问题**。CMS5 是 Web Installer，强制扫描 Creative 设备；本机 `VID_041e` 设备为空。处理：① 插入 NJB3 并确认设备管理器识别（先装 `ctpdusb.inf`）；② 保持弹窗不关、点"重试"；③ 或用 `-Execute -Interactive` 重跑。`install_cms5.ps1` 现会先做设备预检并中止提示 |

## 5. 局限与未知

- 本环境**未接实物 NJB3**，所有安装脚本经过静态检查与语法验证，但**实机成功率需你实测**。
- COM 组件注册是"尽力而为"：Inf 里已写了 CLSID 注册表项，`regsvr32` 主要用于补 TypeLib 注册；
  个别 DLL 在非管理员/受限策略下可能注册失败，但不影响内核驱动绑定。
- `install_cms5.ps1` 的静默参数是 InstallShield 通用值，**不保证**在所有语言版本上有效；
  失败时按脚本提示手动安装。
- 不会、也不应该长期关闭驱动签名强制。测试模式仅用于一次性排错。
