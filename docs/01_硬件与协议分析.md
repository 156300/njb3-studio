# NJB3 硬件与协议分析（带证据）

## 1. 结论摘要

NJB3 是一台 **2002 年、ARM7 架构、IDE 硬盘式、私有 PDE 协议**的 MP3 播放器。它不是标准 USB 大容量存储设备；主机必须通过 Creative 的 WDM 驱动（或开源的 libnjb + 通用 USB 驱动）用私有协议与它通信。歌曲以「数据库记录 + 音频 BLOB」形式存于盘内，**不能靠文件系统层的复制来新增可播放曲目**。

## 2. 硬件证据

| 部件 | 型号 | 证据来源 |
|---|---|---|
| 主控 SoC | Cirrus Logic **EP7212**（ARM720T 内核） | 拆机图 `拆机图片/88_859685_0eb7e369946ba1c.jpg` 芯片丝印；随附 `pdf/EP7212.PDF`、`pdf/DDI0087.pdf`（ARM720T Datasheet） |
| 火线控制器 | TI **TSB43AA82**（IEEE-1394a） | 拆机图 `88_794142_75aab8bdd1cbed9.jpg` / `88_859685_127a38f2c8a0199.jpg` 丝印 "TSB43AA82 26A4HDJ" |
| 音频 CODEC | Philips **UDA1380TT** | 拆机图丝印 "UDA1380TT" |
| 存储 | 标准 2.5" IDE/PATA 硬盘（用户可自行更换，容量 20/40/60GB 版本） | 拆机图排线 + 社区换盘记录（libnjb HACKING "Maintenance Menu…reload the OS…used by people who replace the hard disk"） |
| 接口 | USB 1.1（12 Mbps）+ SB1394/IEEE-1394（400 Mbps） | 原厂手册 `pdf/CREATIVE NOMAD JUKEBOX 3 MANUAL.pdf`：SB1394 用于"fast data transfers"；`ctpdusb.inf` VID/PID 段 |

**关键点**：机内同时有 USB 1.1 与 1394 两条高速/低速通道。原厂定位里 **1394 才是快速传输口**，USB 只是通用口。这对目标 3（提速）至关重要。

## 3. 驱动与协议证据（来自 ctpdusb.inf 原文，证据副本 `evidence/ctpdusb.inf`）

### 3.1 设备标识
```
USB\VID_041e&PID_4101 = "NOMAD Jukebox 3"
```
同 INF 还覆盖 4100(JB2)、4108(Zen)、4110(Zen Xtra)、411B(Zen Touch)、4136(Zen Sleek) 等同系列设备。**NJB3 的硬件 ID 是 041e:4101**。

### 3.2 驱动栈构成
- 内核驱动：`ctpdusb.sys`（x86）/ `ctpdusbx.sys`（x64），服务名 `Jukebox3` / `Jukebox3_x64`，`ServiceType=1`（内核驱动）、`StartType=3`（按需启动）。
- 1394 版本：`ctpd1394.sys` / `ctpdfwx.sys`，服务名 `Jukebox3_1394`。
- 用户态 COM 服务（WMDM 服务提供者）：`CPdeSrvU.exe`（x64 主）、`CTPdeSrv.exe`（x86），注册 CLSID `{2E65E760-B7E6-4CFB-A105-1E8891A00F82}`，AppID `{BD30CBB5-5EA9-4E26-96C2-2E75C58DDBD4}`。
- 支持 DLL：`ctpde.dll`、`CTPmsMan.dll`、`CTPmsWma.dll`、`ctjb2sp.dll` 等。

### 3.3 传输参数（INF `DriverHwPropReg` 段）
```
HKR,,WMDMSPCLSID,,"{DF878EB3-5A77-405C-BF36-FAF4916BD25C}"
HKR,,OptimalTransferSize,0x10001,0x40000     ; 256 KB
HKR,,UseMetadataViews,0x10001,0x1
HKR,,ShowInShell,0x10001,0x1
```
`WMDMSPCLSID` 明确这是 **Windows Media Device Manager 服务提供者**——上层应用（MediaSource/PlayCenter/WMP）通过 WMDM 接口访问，而不是标准文件 API。

### 3.4 固件升级通道
`ctpdusb.inf` / `ctpd1394.inf` 的注册表项都提到 NJB 系列固件；固件包内 `JB3Upgrade_1_40_06.exe` 的 Readme（证据副本 `evidence/firmware_1_40_06_Readme.txt`）说明：升级时"Windows 检测到播放器 → 点 Upgrade → 播放器自动重启 → Rebuilding Library"，失败则进入 **Rescue Mode → "3: Reload OS"**。这与 libnjb HACKING 描述的 FBOOT/FRESC（救援模式，位于机内 flash，硬盘崩溃后仍存活）一致。

**推论（静态推断）**：固件/OS 镜像由主机经 PDE 协议推送，OS 主体存放在硬盘上；机内 flash 保留引导与救援程序。因此换硬盘后可用 "Reload OS" 恢复，但**不能由此推出可以刷入自定义通用文件系统固件**——见 docs/03。

## 4. 数据模型：为什么"拷文件进去"不管用

三条独立证据交叉印证：

1. **原厂手册**（`pdf/CREATIVE NOMAD JUKEBOX 3 MANUAL.pdf`，第 4-9 节 "Transferring data files"）：
   > "Audio tracks in MP3, WAV or WMA file formats will be stored as data files when they are transferred from your PC; **they cannot be played by your player**."
   即 File Manager 传的是"数据文件"，与可播放曲库是两个空间。

2. **libnjb 官方 HACKING**（Debian sources `libnjb/2.2.5/HACKING`）：
   > "the jukeboxes are actually not filesystems: internally, the jukeboxes are databases. A 'file' … consists of a database entry with several metadata components, such as artist, title, original filename, and the actual MP3/WAV/WMA-file is just a binary large object (BLOB) in this database entry."
   > "a filesystem component capable of writing … would have to include something like an ID3 tag parser to extract metadata from the file and insert this into the database."

3. **社区事实**：njbfs（Linux 内核文件系统项目，SourceForge）长期处于 Alpha、2013 年后无更新，正是因为这个"数据库≠文件系统"的障碍；主流方案始终是用用户态库（libnjb）通过 PDE 协议管理曲库。

**结论**：新增可播放曲目的唯一可靠途径是**通过 PDE 协议调用设备 API**（上传音轨的同时写入元数据记录）。这正是目标 1 中传输软件要做的事，也是目标 2b 不可行的原因。

## 5. 开源工具生态（libnjb）

libnjb 2.2.7 是用户态 C 库 + 一组命令行工具，跨平台（Linux/BSD/macOS/Windows via libusb）。相关工具（名字来自 OpenBSD ports 的 libnjb 文件清单）：

| 工具 | 功能 | 对应需求 |
|---|---|---|
| `njb-handshake` | 连接握手测试 | 驱动自检 |
| `njb-tracks` | 列出曲库 | 曲库管理 |
| `njb-sendtr` | 上传音轨（写元数据） | **传歌 + ID3 索引** |
| `njb-tagtr` | 修改曲目标签 | **ID3/元数据编辑** |
| `njb-gettr` | 下载音轨 | 备份 |
| `njb-deltr` / `njb-delfile` | 删除 | 整理 |
| `njb-playlists` / `njb-pl` | 播放列表管理 | **播放列表 / m3u** |
| `njb-setpbm` | 设置播放模式 | **机器设置控制** |
| `njb-settime` / `njb-getusage` | 时间/容量信息 | 状态查询 |
| `njb-fwupgrade` | 固件升级 | 固件维护 |

我们的 `njb3_transfer.py` 就是对这些命令的封装与批处理增强（含内置 ID3 解析，避免额外依赖）。

## 6. 局限与未知

- **未做实机验证**：本分析基于静态材料；硬件 ID、协议、数据模型证据充分，但"Win11 实机传输成功率"需用户实测。
- **数据库二进制格式未公开**：本方案不尝试直接解析/改写盘上数据库（高风险且无公开规范）；而是通过 libnjb/PDE 这一"官方语义"通道操作。这是稳定性与可行性的最佳权衡。
- **固件镜像内容**：从 `JB3PCFW_US_1_40_06.exe` 内提取出的 `JB3Upgrade_1_40_06.exe` 是自解压的刷机程序，未发现明文 FBOOT/FRESC 镜像；固件为打包/加密分发，无可修改的工程文件。
