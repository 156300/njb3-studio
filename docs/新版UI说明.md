# NJB3 Studio —— 三工作台（当前发布版 0.1.1-261123）

> 这一版是**整页工作台 + 模块化内部布局**：三个整页工作台由顶栏按钮切换，无页签、无眉头；
> 控制工作台内部模块可拖动、贴边、调大小。
> **源文件 `scripts/njb3_gui.py` 等一行都没改**——新版通过子类化复用原程序 100% 的业务逻辑。

---

## 一、怎么运行

**方式 A（源码）**：在仓库 `src/ui_next/` 目录下运行 `启动新版UI.bat`（需 Python 3.13 + pyusb + libusb）。

**方式 B（绿色包，推荐）**：从 [releases/](../releases/) 下载
`njb3-studio-0.1.1-261123-win-x64.zip`，解压后双击「启动 NJB3 Studio.bat」。
程序为单文件绿色版，无需安装 Python / VC++ 运行库；首次使用需先双击
「安装 WinUSB 驱动.bat」装一次驱动（自动 UAC 提权）。

**0.1.1-261123 相对 0.1.0-261123 的改动**：修复播控工作台「清单内的歌曲」垂直滚动条消失
（6 列扩宽后 `pack` 把滚动条压成 1×1，改用 `grid` 保留固定宽列）。版本号递增。

**0.1.0-261123 相对 v46 的改动**：状态栏右侧显示版本号；修复绿色包 bat 编码
（GBK+CRLF）；修复驱动签名 NO_CERT 并兼容精简版 Win10/Win11。

（源码运行需放在含 `runtime/libusb-1.0.dll` 的结构内，见 [构建与开发.md](构建与开发.md)）

## 二、v46 布局（界面基础，后续版本沿用）

### v46 相对 v45 的改动

- **按机器序号缓存曲库，连接快读**：首次连接某台 NJB3（按 `read_id()` 的 16 字节序号识别）完整读取曲库（约 57s / 4827 首）并把慢字段 `filename`、`folder` 按 trackid 存到 `njb3_library_cache.json`；以后每次连接只快读基础曲库（约 3.3s），再按 trackid 从缓存补回扩展字段，实测快约 17 倍且扩展字段 100% 补齐。
- **匹配机制**：主键 = 设备序号 hex 精确匹配；缓存只存慢字段，标题/艺人/时长等基础字段始终取设备实时值，所以设备增删曲目或改元数据不会被旧缓存覆盖；换机器自动用各自序号的缓存，互不串扰；缓存损坏/版本不符/序号读不到都自动退回完整读，不阻断连接。
- **手动完整刷新按钮**：「设备信息与数据刷新」模块里的「刷新曲库和播放清单」改为 **「刷新完整曲库和播放清单(速度慢)」**，点它强制完整重读并覆盖该序号缓存，用于设备曲目有增删或元数据变更后的手动同步；平时连接与传输后刷新都走快读缓存。
- **真机验证**：首次完整读 57.12s / 4827 首并建立缓存；再次读 3.20s / 4827 首、扩展字段全补齐；强制刷新 57.13s 且缓存更新；设备全程 STOP + recover + close 正常归还（`VERIFY OK state=1`）。

### v45 相对 v44 的改动（本轮）

- **启动默认钉在控制工作台**：无论旧配置记住哪一页，每次启动都切到「控制工作台」，设备状态与播控触手可及。
- **两处单次播放建议**：播控工作台总开关按钮与「开启播控模式」确认弹窗都加上「强烈建议NJB3使用单次播放模式」；建议播放机设为单次播放，避免连播与软件播控互相冲突。
- **曲库慢速根因实测（未改协议代码）**：真机逐阶段计时，连接总耗时约 62s，其中 `list_tracks(extended=True)` 占 56.8s（28 批 × 2s，4827 首）；设备信息 0.17s、播放清单 0.17s、9 个清单成员 3.8s、队列回读 0.04s（固件不支持，回退缓存）。
- **排除项**：把 bulk read 从 1MB 改为 64KB 或 4KB，耗时仍约 57s → 不是 WinUSB 驱动或主机读取长度问题。改用 `list_tracks(extended=False)` 同样 4827 首仅 3.27s；单独请求 `F_FNAME` 或 `F_FOLDER` 任一字段都会回到 ~56s → 慢在固件逐首查文件名/文件夹（约 11ms/首）。
- **待选优化（尚未实施）**：连接时先用 basic 曲库（3.3s）渲染，仅在下载/元数据编辑需要时再取扩展字段；或把扩展元数据缓存到本地，首次慢、后续快。

### v44 相对 v43 的改动（本轮）

> v43 的"曲末 300ms 高频 + 0.35s 提前量 + 差速补偿"经真机实测被否决并撤销：
> 它造成"提前触发一次 + 到 total 再触发一次"的双重调度，表现为曲末乱跳。

- **真机实测结论（固件 1.40.6）**：① 播放全程 `state=0`（playing），曲目播完**从不报 stopped**，elapsed 归零后循环重播同一首；② 中途 `play_track` 立即切歌（指令本身 0.5~1s）；③ 设备时钟与 PC 几乎 1:1（43s 标称实测 43.9s 归零）。
- **曲终恢复单一信号**：本地计时每秒 +1，到 total 由基类 `ended` 路径**唯一一次**触发曲终调度；彻底删除 v43 的 `_tick_tail_align`（高频观测 + 提前量），杜绝双触发乱跳。差速仅保留"可学习"用于参考，不再驱动切歌。
- **保留 v43 的正确部分**：播放前 `clear_play_queue()`（队列只留当前曲，杜绝设备自行切到残留旧曲）。
- **拖入播控队列修复**：副套树（传输页"机器内歌曲"）发起拖动时，原来按主树 `identify_row` 取 ID 会落空；v44 改为从事件来源树取选中 ID。同时释放时先判定"播控队列"目标，未选播放清单也能拖入。
- **真机连播验证**：3 首短曲连续播放，本地计时与设备 elapsed 全程同步（尾部误差 ≤1s），每次曲终只切一次、无乱跳；设备按纪律 STOP + clear + recover + close 正常归还。

### v42 相对 v41 的改动（本轮）

- **右键删除修好**：机器内歌曲右键“删除 / 修改 / 同步 / 加入播放清单 / 增加至”和播放清单右键“改名 / 刷新成员 / 删除列表”都绑定到**触发事件的那一棵树**，不再等菜单弹出后误读播控页主树。
- **复制控件全面核对**：传输页“搜索”按副套机器内歌曲表定位；机器内歌曲拖到播放清单时也记录真正发起拖动的树，避免拖放落到错误页。
- **删除不再弄坏播放清单**：libnjb 源码明确记录“把清单里所有歌删光会生成 corrupt empty playlist”。v42 在删除曲目之前，先把所有受影响清单用 `replace_playlist` 重建（成员为空也新建空清单再删旧清单），从根本上规避固件把清单删坏、随后 rebuilding library。
- **删除后同步清理缓存**：曲库、播放清单成员、当前清单曲目、播放队列中的陈旧 ID 一并移除；重建清单产生的新 ID 只在当前选中清单时改选中项，批量删除不会抢走用户选择。
- **空/损坏清单不再中断连接**：读取播放清单成员超时按 0 首处理并记录警告，不再把单个坏清单的 USBError 抛给全局 worker 触发反复“自动释放 + 重连 + 重试”。

### v41 相对 v40 的改动（本轮）

- **删除选中弹窗加进度计数**：仅传输工作台“机器内歌曲 → 删除选中”的弹窗右上角显示 `x/N` 首数，进度条改为确定模式；上传、刷新等其他弹窗不显示计数。

### v40 相对 v39 的改动（本轮）

- **按钮选中归属修正**：
  - 传输工作台左下“刷新曲库 / 下载选中 / 删除选中 / 改元数据”只读取本页**机器内歌曲**；
    播放清单下的“改名 / 删除”只读取本页**播放清单**，不再串到播控工作台的框体。
  - 曲库、播放清单、清单内歌曲每次重绘后**恢复原选中行**，“没有选中效果、按钮点不动”问题消失。
- **清单按钮归属纠正**：“移除已选 / 清空清单”只在**传输工作台**的“清单内的歌曲”下方；播控工作台不再添加。
- **机主名读写按 libnjb 帧格式**：写 0x0113 时补齐 libnjb 要求的尾部 `00 00`（长度 = UCS2 字节数 + 4）；
  读时按 `status + strlen + frameid + UCS2` 解析，不再把帧头当名字。
- **闪烁消除**：顶栏“断开设备”与播放页“音量 / EAX”只跟随连接状态，不再被每 2 秒一次的播放状态同步短占 worker 触发闪动；
  仅真正传歌期间禁止断开设备。
- **播放模式全部软件逐曲调度**：
  - ★GO（任意模式）：播放当前选定，随后选定跳下一首；软件播放只播放当前选定。
  - 单曲：曲终只把软件状态归位，**不发停止指令**；单曲重复：重新播放当前曲目。
  - 顺序：曲终播放选定并跳下一首，最后一条播完发停止；循环：往复不停。
  - 随机 / 随机重复：曲终给刚播完曲打软件内部“已播”标签，再播放选定并随机跳到未播曲；
    随机播完发停止；随机重复全标后清标、随机跳非当前曲继续。
- **定位后计时重建**：seek 后立即把内部已播秒数刷到目标位置；每次播放新曲都从 0 起算，
  避免带着上一首的定位秒数计时导致后续歌曲提前被切走。

## 三、皮肤与系统跟随

顶栏点 **🎨 外观**，打开外观设置对话框（foobar2000 风格：选预设即时预览、确定才保存、取消还原）。

**4 套皮肤**：
- **深空石墨**（默认）：近黑不纯黑 + 青绿强调，参考 Resolume Arena
- **午夜蓝**：蓝黑底 + 亮蓝强调
- **云白**：白底 + 墨绿强调
- **暖米**：米色底 + 棕橙强调
- **跟随系统**：随 Windows 浅色/深色应用模式自动切换（每 4 秒检测）

对话框内实时显示 **WCAG 对比度校验**，所有预设正文对比度 ≥ 5.7:1（AA 要求 4.5:1），正文达 AAA 级。

切换会同步到：顶栏、信息条、所有面板标题栏/页签、Treeview 三态焦点色、按钮/输入框/分隔条。皮肤保存在 `studio_theme.json`。

## 四、设计系统（Design Tokens）

由 UI Designer 规范建立，语义化 token（控件只引用语义名，不写死颜色）：

| 类别 | token |
|---|---|
| 底色 | `bg` 工作区 / `chrome` 顶栏 / `panel` 面板 / `header` 标题栏 |
| 文字 | `text` 正文 / `text_dim` 次要 / `header_fg` 标题 |
| 强调 | `accent` + `accent_fg`（按钮） |
| 焦点三态 | `select_bg`（焦点-灰蓝）/ `idle_bg`（失焦-中性灰）/ `warm_bg`（舞台-暖黄） |
| 语义色 | `ok` / `warn` / `error` |
| 结构 | `border` 1px 边框 / `sash` 分隔条 / `tab_bg` / `tab_active` |

设计原则：**简约大方**（低饱和中性底 + 单一强调色）、**条框清晰**（1px 边框、工作区<面板<标题栏三级层级）、**易读易用**（焦点三态可辨、对比度达标、拖拽反馈明确）。

## 五、技术实现与兼容

- **接入方式**：`StudioApp(base.App)` 只覆盖 `_build_ui()`，其余 5000 行业务逻辑（设备连接、曲库、播放、传输、舞台队列）全部继承原样。
- **状态不丢**：停靠重排只重算 place 坐标，业务控件（Treeview/变量/绑定）从不销毁重建。
- **兼容层**：`_NBShim` 把原 `self.nb.select(self.tab_xxx)` 转发到整页切换。
- **两套停靠引擎**：主区为 3 个整页（`show_header=False`）；控制工作台为 6 个可停靠模块（`slim=True`）。
- **日志上限**：布局节点支持 `min_ratio` 与 `max_ratios`，日志最多占 35%。
- **主题系统**：`njb3_theme.py`（配色 + 系统检测 + WCAG 审计 + Combobox readonly 配色）
