# WinUSB 驱动安装与排错

## 1. 为什么必须换驱动

NJB3（VID_041E / PID_4101）出厂绑定 Creative 的 `ctpdusb.sys` 内核驱动，它独占 USB 端点。
用户态程序（pyusb / libusb）无法访问设备。解决方式是把它换成 Windows 自带的 `winusb.sys`：

- `njb3_winusb.inf`：用 `Include=winusb.inf` / `Needs=WINUSB.NT` 绑定微软内置 WinUSB 驱动；
- `njb3_winusb.cat`：INF 的签名 catalog，由 `make_cat.py` 生成；
- `njb3_driver.ps1`：把自签证书装入本机信任库、生成 CAT、`pnputil /add-driver` 安装并绑定；
- `install_winusb.ps1`：上面的精简安装入口。

自签名证书只作用于**本机**，用于测试驱动安装。

## 2. 安装步骤

1. 关闭所有正在运行的 NJB3 工具（旧版会占用接口）。
2. 右键 `安装 WinUSB 驱动.bat` → **以管理员身份运行**。
3. 按提示完成，重新插拔设备。
4. 打开 NJB3 Studio，控制工作台应显示设备已连接。

也可以手动执行：

```powershell
powershell -ExecutionPolicy Bypass -File src/scripts/njb3_driver.ps1 -Install
```

## 3. 常见错误码

| 错误码 | 含义 | 处理 |
|---|---|---|
| `0x80096010` / `TRUST_E_BAD_DIGEST` | CAT 里的文件 digest 格式不对 | 确认使用本仓库的 `make_cat.py`（生成二进制 `04 14 + SHA1`，不是 hex 字符串） |
| `0xE0000247` | 驱动包安装失败 | 多由上面的 digest 错误引起；若证书已入库，检查 LocalMachine 私钥权限 |
| 退出码 7 | 安装流程中途失败 | 查看 PowerShell 输出的具体步骤，以及 `C:\Windows\Inf\setupapi.dev.log` |
| libusb 打不开设备 | 设备仍被原厂驱动占用 | 确认驱动已切换（设备管理器里应为 WinUSB 设备），并关闭其他工具 |
| 设备反复重插 | 驱动绑定未生效 | 以管理员运行 `install_winusb.ps1` 后重启 |

## 4. 排错方法

- 看 `setupapi.dev.log` 里 `!!! sig:` 与 `!!! ndv:` 开头的行，它们会直接给出失败阶段。
- `make_cat.py -SelfTest` 可单独验证签名链路：`WinVerifyTrust=0x800B0109` 表示 digest 正确，
  仅剩证书信任待处理；若仍是 `0x80096010` 说明 digest 生成有问题。
- 原厂驱动与 WinUSB **互斥**，同一时刻只能绑定一个。需要回到原厂 CMS5 时，
  在设备管理器里更新驱动指向 Creative 的 INF。

## 5. 1394 备用路线

NJB3 部分型号带 IEEE-1394 接口。`src/scripts/install_1394_host.ps1` 提供廉价 VIA/TI 1394 卡的
驱动检测与绑定辅助。这是备用路线，不是本项目主线；详见 [05_1394火线卡适配说明.md](05_1394火线卡适配说明.md)。

## 6. 合规声明

- INF 使用微软**系统自带**、已 WHQL 签名的 `winusb.sys`，项目不分发任何第三方内核驱动。
- 自签名证书仅用于本机测试，私钥不要分发。
- 本项目不分发 Creative 的专有驱动、固件或 CMS5 软件。
